## Calibration to apply

- Findings from every seat count; labels are advisory and the orchestrator owns severity. Executing seats systematically escalate; static-only seats moderate — on the same underlying finding. Trust finding convergence, not label agreement. Family-disjointness and author-lineage non-certification still bind. The seat's literal vote fence is authoritative over any orchestrator prose-mapping; votes are append-only, one per actor, no supersede.
- **Classify a seat by its ACTUAL tool surface at dispatch time, not by engine family.** pi-sdk seats on this fleet are execution-capable (verified 2026-07-23: GLM ran pytest in a detached worktree unprompted). Harness drives calibration as much as model does — kimi k3 under kimi-code's opinionated ACP harness voted strict on a subject-severity a lean-harness seat historically labelled soft.
- **Do not average a seat into a single label prior.** Within-model variance is real across runs, not just across pins: qwen38max returned approve/P2 and needs-changes/P1 on the SAME subject and brief hours apart. Treat repeat runs — and multiple pins of one model — as independent samples, never redundancy.
- Opus and Fable have proven fail-closed abstain discipline: when the subject or verification path is unavailable, they abstain and disclose the ceiling instead of inventing evidence. On this host Opus can verify the ARB store content-hash pin but cannot recompute the raw-body digest; Fable's piext ceiling can recompute the raw digest. Always provide both labeled pins and STOP only if both fail. The earlier dual-hash abstains were cured by this both-pins rule. Their read-only PROD ARB Memory access was fixed fleet-wide on 2026-07-22.
- Opus 5 vs Opus 4.8 are **not interchangeable within the family** — rostered separately on DC-007 (`disagreement-corpus.md`), a same-brief/same-commit/same-`asdk`-oneshot split where **model was the only variable** and both seats were execution-blocked. 4.8 returned APPROVE_WITH_NITS (0 P0, 0 P1, 5 P2) and affirmatively cleared a door claim; Opus 5 returned REQUEST_CHANGES (1 P0, 2 P1, 8 P2). Ground-truth adjudication (code, orchestrator-re-verified) made Opus 5 lone-correct ×2 — including a P0 audit plane never wired in production that 4.8 declared correctly implemented and tested. The same P0 came back on a second, execution-capable harness, so the delta is **model-attributable, not tool-attributable**, and Opus 5 reached it by static reading alone. Do not treat 4.8's approval as covering a subject Opus 5 has not seen; on high-stakes subjects run both (they dispatch concurrently — separate seat processes) and count them as independent samples.
- GLM — **RE-BASELINED 2026-07-23 as an executing escalator; its historical "soft labels" prior is RETIRED.** On the re-baseline panel it was the only seat of three to find the ground-truth defect and it PROVED it: detached worktree at the ref, ran pytest, identified the false-green CI path, attributed severity precisely, labelled needs-changes/P1 — correct. Expect executing-seat escalation, not moderation. Best epistemic hygiene on the fleet; only reviewer to date to detect embedded prior-review reports in a brief and refuse to launder their claims. Privacy/grant/redaction/evidence remains its strong lens; ask for INLINE reports. Liveness: the stall history is a risk, not a constant (the re-baseline run was the panel's cleanest, ~11 min, no stall) — keep ~1800s ceilings and a pre-staged `timed-out` vote as insurance.

Two samples 2026-07-23: findings real and evidence-first in both, labels unstable across them (P2→P1 on the same subject). ## Reliability ledger and standing cures

- Five-seat manifest-only timeout: 133 KB artefact inlined into every prompt → stage bytes or use an authenticated pointer, and preflight capabilities.
- Opus/Fable abstained because their launch path lacked the memory read tool → fixed with in-Python tier resolution against the PROD store; verify local deployment before relying on it.
- GLM rode a stalled turn to the 3600-second ceiling twice → cap reviews around 1800 seconds and stage `timed-out` early.
- AGY then Grok burned rounds on ambiguous digest domains → label and pin both the store content hash and raw-body SHA-256; STOP only if both fail.
- Vote re-fires from non-canonical stance or missing severity → quote canonical stance vocabulary; include severity (`none` default is tolerated).
- Three-seat wedge and crash-looping restarts (2026-07-22/23): macOS TCC blocked launchd-context reads of the workspace volume — an identity mismatch, the grant named a `bin/python3.14` path while seats actually run under Python.app → grant Full Disk Access to the binary the seat REALLY executes as; `com.example.wedgeprobe` verifies in ~30s; bounded git ops keep a wedged seat failing fast instead of hanging.
- Two gate rounds lost to a driver crash (2026-07-23): a Python-3.14-only `Path.read_text(newline=)` call in the FABA drivers, with CI pinned to 3.14 giving a false green while the venv the drivers actually run under was 3.12 → after pulling driver changes, run the driver tests on the venv the drivers execute under, not on CI's pin. A CI pin that differs from the runtime venv is a green light for a red build.
