## 3. Design decisions

### 3.1 Where the close finds the refs: committed rows, never recollection

`panel_audit.reconcile`'s doctrine — "Ground truth is the committed rows, never the orchestrator's recollection" (`panel_audit.py:5-6`) — extends to the ref sets:

- **Binding set (D1 resolved (b)):** the manifest declaration only. Under the deferred Slice-2b join ((a), §2A), it becomes the union of `gate_admission` rows and any manifest declaration.
- **Cross-check semantics (unchanged by the 2b join):** a `claim_refs` key on the manifest or verdict payload is checked **only when present** — absent means "no cross-check", never "declares empty". Present-and-unequal refuses `claim_refs_mismatch` (mirroring the roster equality check, `panel_audit.py:66-69`); under the Slice-2b join a manifest set omitting an admitted ref (including `[]`) refuses with the `undeclared_admitted_ref` gap detail. Declared-`[]` or absent declaration closes as today — that is R1's named bypass, unclosed this slice by the D1 resolution.
- Recorded dispatch-time facts (§5.2 resolution record, `gate_audit`) are **never consulted** — fresh view reads only (spec `:324-336`; the §11 wedge test, spec `:719-723`).
- **Order inside `close_core` (revised — CO-r2-P2-1, GROK-S2R2-G4 pt 1):** reconcile → **claim-key state triage** → re-resolution → claim/emit. Triage: key exists ∧ hash matches ∧ stream has verdict → `emitted`/0 (read-only replay); key exists ∧ hash matches ∧ no verdict → `orphaned`/6 (operator sees the DEL-and-rerun message, `run.py:596-601`); key exists ∧ hash differs → `different_verdict`/5. Re-resolution therefore runs only on first-close and on orphaned-recovery re-runs (post-DEL, `run.py:596-601` — no verdict was emitted, so fresh truth governs), and an inadmissible ref can no longer mask `orphaned` or `different_verdict` behind exit 8. Replay of an emitted verdict whose ref has since expired/retracted stays `emitted`/0 (idempotent; the verdict is history, not a new authorization).
- **`collect_refs` reads its own manifest row [CO-r2-P2-5]:** reconcile's exactly-one-manifest guarantee (`panel_audit.py:39-44`) holds for reconcile's snapshot; `collect_refs` issues a second read, and `audit_events` is append-only but appendable-between-reads. If its own read finds manifest count ≠ 1 it refuses with gap `manifest_count_invalid_at_close` — fail-closed, named, no guarantee borrowed across reads.

### 3.4 Sampler design

**What it is.** The consumer's randomised spot-check of §7.4: occasionally re-verify a claim despite a clean attestation (spec `:551-559`) — the rival-instrument probe rule as standing machinery (`docs/pipeline-operating-manual.md:163-183`).

**Pool.** Claims with `confirmed_now = true` (the view's own predicate, `schema.sql:414-415`) and at least one *counting* attestation. Requiring `confirmed_now` keeps expired accepted-risk claims — already unable to authorize work — from consuming sampling budget; they re-enter when overridden (Exit B), so no signature permanently graduates out of the *admissible* population (honesty note: the no-graduation guarantee is scoped to claims currently able to authorize work). The pool is a SQL view `spot_check_pool_v` whose counting-attestation predicate is **the same WHERE clause verbatim as `schema.sql:419-422`** (aggregates differ by necessity), with the population-alignment test as the enforcing rail (T3). Retracted claims are out; unconfirmed claims are out (revisitable, §9).

**Weights.** `w = 1.0 × PROSE_W^[any counting attestation has falsifier_kind='prose'] × DEGRADED_W^[decorrelation_provenance='degraded']`; `PROSE_W` default 4.0 (`ARB_SPOT_CHECK_PROSE_WEIGHT`), `DEGRADED_W` default 2.0 (`ARB_SPOT_CHECK_DEGRADED_WEIGHT`); multipliers < 1.0 refused at config parse (`spot_check_invalid_weight`). Prose weighting per spec `:507-509`; degraded per spec `:227-229`. Pool membership guarantees provenance ∈ {'wire','degraded'} (`schema.sql:433-442`), so the floor weight is 1.0 by construction (tested).

**Weight-input integrity — residual R6.** `falsifier_kind` is participant-attested (`gate_store.py:100,115-121`; domain CHECK `schema.sql:363-364`). Enforced strength stated honestly: "the die lands more often on *attestations labeled prose*", not "on prose". Partial mitigation, tasked: the sampler ticket template (T8) instructs the rival seat to check the recorded `falsifier_kind` against the falsifier text and flag mismatch — the sampler itself becomes the consistency probe. Full integrity is deferred with 1f/1g.

**Draw.** Weighted sampling without replacement (Efraimidis–Spirakis, `u^(1/w)`, seeded `random.Random`), `k` per draw (`ARB_SPOT_CHECK_K`, default 1). Claims with an open sample (`status IN ('drawn','dispatched')`) are excluded. Every draw persists sample id, claim id, seed, weight snapshot, pool size, drawn_at.

**Stale-open policy.** Samples open longer than `ARB_SPOT_CHECK_STALE_DAYS` (default 14) are auto-voided by the draw command with reason `stale_open_sample` (sweep at draw time — no new daemon), returning the claim to the pool; the draw report counts open samples and ages. Test (T5).

**Coverage floor — corrected worked example [CO-r2-P2-3].** Stratification buys **class** coverage, not member coverage: in a 99-prose/1-command pool, the lone command claim's weighted per-draw probability is `1/397 ≈ 0.0025`; the stratified sweep guarantees its stratum one draw (probability 1.0 within a singleton stratum). (The inverse 1-prose/99-command case moves a given command claim only `1/(4+99)=0.0097 → 1/99=0.0101` — stratification is not a member-level fix, and member-level coverage is already honestly bounded by the scope rule below.) Therefore the **weekly sweep draw (k=2) is stratified**: one draw from the prose-flagged stratum and one from the non-prose stratum whenever both are non-empty (degraded weighting applies within each stratum); the per-close draw stays fully weighted. Pinned statement: each **class** present in the pool receives ≥ 1 expected sweep draw per week **when the weekly sweep job runs** — the floor inherits R7's process strength [GROK-S2R2-G2]; T5 proves the draw function, not fleet coverage. Test (T5): two-class pool ⇒ sweep contains one member of each class.

**Dispatch identity, seats, cadence, budget.**
- *Who:* the warm orchestrator (or operator job) runs `python -m arb_memory spot-check-draw` and dispatches tickets; the sampler never dispatches.
- *Seats:* re-verification rides the **exempt lane** (spec `:91-96`) on a seat whose model family differs from both the claim's `author_family` and every counting attestation's `verifier_family`; `spot_check_pool_v` exposes the family sets. No third family → sample `void`, reason `no_rival_family_available`, surfaced in the draw report.
- *Cadence — an owned process, not phantom machinery:* the weekly sweep (`k=2`, stratified) runs as an operator launchd/cron job whose artefact (plist/cron line) is added in T8's deploy note with a named owner (bridge host operator). The per-close draw (`k=1` after every close whose binding ref set is non-empty) is an orchestrator process step documented in T8 — **[CO-r2-P2-7; D1 resolved (b)]: its trigger population is voluntary declarations only, so until orchestrators declare (or the Slice-2b join lands), the weekly sweep is effectively the sole cadence and the steady-state budget is ≤ 2 exempt-lane rounds/week (+1 per declaring close); under the Slice-2b join the trigger becomes every close with admitted refs.** Residual R7: cadence is process-strength; no code path triggers a draw.

**Scope language (binding on all sampler output):** a confirming sample establishes *that claim's* probe-claim link, nothing else. Reports state scope as `k of N pool`, per-claim. The ticket template (T8) carries the rule verbatim.

### 3.5 Refute consequence: record, adjudicate, then act — retraction is an owner act [SOL-R2-F2, CO-P1-3; r1 GROK-P1/S2-G5, SOL-F2 lineage]

r1 auto-retracted on refute (broken: irreversible-in-slice on participant-strength evidence). v2 recorded refutes but left them unadjudicable — "decline retraction and void the sample" was impossible against T5's terminal transitions (SOL-R2-F2). v3 completes the state machine:

- **On `refuted` (spot-check-record):** the consumer, in one transaction, (1) requires an outcome artefact that **resolves** (`fetch_artefact`) plus a caller-declared verifier seat/family and a non-empty rationale — the allowlisted-author check is deliberately **not** applied (§2 item 5). **Enforced claim, worded at mechanism strength [CO-P1-3]: "a resolvable artefact reference, recorded alongside a caller-declared verifier seat/family and a non-empty rationale; nothing binds the artefact's author to the declared seat."** That wording — not "authored by a recorded participant seat", which no mechanism reads (`artefacts.author` is consulted by nothing on this path, and is client-supplied on the direct-bus ingress, `gate_store.py:16-29`) — is carried verbatim into T6's CLI help, the sample-row comment, R5, and the T8 ticket template. A cheap `artefact.author == verifier_seat` tripwire is deliberately **not** added: legitimate artefacts are authored by the publishing identity, not the verifier seat, so the check would be near-inert while inviting exactly the overclaim it pretends to prevent. (2) Marks the sample `refuted`. (3) **Does not touch `claims`.**
- **Adjudication (new — the missing owner action):** append-only `spot_check_adjudications` table (T3) + owner CLI `spot-check-adjudicate --sample-id --decision {retract,dismiss} --by --rationale` (T6). Refusals: `adjudicate_wrong_status` (sample not `refuted`), `adjudicate_already_adjudicated`, `adjudicate_empty_identity`, `adjudicate_empty_rationale`. `--decision dismiss` (wrong refute): the sample transitions `refuted → void` with `void_reason='refute_dismissed'`, one transaction with the adjudication row — the claim was never touched, the escalation clears, the history stays. `--decision retract` (refute upheld): calls `gate_store.retract_claim` (retraction row records the triggering `sample_id`); the sample stays `refuted` with its adjudication row.
- **Transitions enforced (T6):** `drawn/dispatched → confirmed|refuted|void` via `spot-check-record`; `refuted → void` **only** via `spot-check-adjudicate --decision dismiss`; everything else refuses `spot_check_sample_closed`.
- **Escalation, not silence:** `spot-check-report` (T6) lists open samples with ages and flags **unadjudicated** refutes (`status='refuted'` with no adjudication row); adjudicated refutes are listed, not flagged. Owner notification is a process step in T8's ops note.
- **Retraction = owner CLI:** `python -m arb_memory retract-claim --claim-id --by --rationale` → `gate_store.retract_claim`: refusals `retract_unknown_claim`, `retract_wrong_status` (only `confirmed → retracted`), `retract_empty_identity`, `retract_empty_rationale`; append-only `claim_retractions` row + `UPDATE claims SET status='retracted'` in one transaction. Retraction then flows through the one view: dispatch refuses `unconfirmed_claim` (`claim_gate.py:232-238`), in-flight closes refuse `retracted_claim` — a wasted round at most (spec `:600-602`).
- **Terminality, stated at full strength:** no Slice-2 path returns a retracted claim to `confirmed`. Recovery from a **wrong refute** is now a real mechanism (dismiss, above — before the irreversible step); recovery from a **wrong retraction** has no in-slice mechanism and is named as constitution-layer break-glass (direct store operation by the owner). Auto-retract on machine-strength refutation is a named deferred obligation of the 1g slice.
- **Owner fork (§9, still open):** the owner may direct auto-retract now, accepting the named risks. The implemented default is adjudicate-first.
