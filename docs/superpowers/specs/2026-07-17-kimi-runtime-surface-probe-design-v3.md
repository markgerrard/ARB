## 2. The inversion

> **v1:** B discovers (from history), A corroborates. — *broken: history is unrecoverable.*
> **v2:** **A discovers** (from a live turn), **B proves minimality** (against live turns).

This deletes defects 1, 2 and 6 by construction: there is **no reconstruction step**, so there is
nothing for truncation to destroy, and the historical corpus carries **no evidentiary weight**.

The property Mark approved survives intact: **two mechanisms, blind on different axes, and the delta
is the deliverable.**

| | **A — discover** | **B — prove minimality** |
|---|---|---|
| Question | *What does a real review turn touch?* | *Is every allow load-bearing?* |
| Mechanism | `fs_usage` (3 modes, §4) over a live R2 `auto` turn | **class-level drop-one against LIVE turns** |
| Yields | observed superset: paths, execs, endpoints | the subset that is actually required |
| Blind to | need vs. incidental noise ⇒ over-allows | anything outside what A observed |
| Cost | **~4 turns (~1h)** — discover→measure, not one turn (§4.0) | ~6–8 turns (§5) |

**The delta rule, corrected.** v1 said "in A, not in B ⇒ candidate to deny." That is **wrong for the
silent-degradation class** and was flagged by two seats independently. Corrected:

- **In A and required by B** → enters `SandboxSpec`.
- **In A, not required by B** → **HOLD FOR ARGUMENT — never auto-deny.** A path can be touched,
  be load-bearing, and still not break the oracle when denied (the program degrades quietly). Each
  such row needs a named human/panel argument to deny. Denial-by-default-of-the-delta is how a
  quietly-broken profile ships.
- **Required by B, not in A** → **one of the instruments is lying.** Read this row first.

## 3. Corrected bootstrap profile (fixes defect 4)

The trace runs kimi in `auto` before a profile exists. Chicken-and-egg, resolved by a coarse-but-real
boundary — **now including the seat-state paths v1 omitted**:

- **read:** broad (we are measuring reads, not constraining them yet)
- **write:** isolated worktree · scoped TMPDIR · **`~/.kimi-code/**` (seat state/cache — the v1 omission)**
- **network:** the API endpoint only
- **paths:** `/private/tmp`, never `/tmp` (§8)

**Bootstrap self-test — REQUIRED, and it gates A's data:** the R2 `auto` turn **must reach the §6
oracle under the bootstrap profile** before any of A's output is trusted. If it does not, A is
measuring a degraded agent and its "superset" is an artifact. **This gate is what defect 4 buys** —
without it, a poisoned trace is indistinguishable from a clean one.

The bootstrap profile is an **instrument**. It does not enter `SandboxSpec`.

## 4. Instrument A — three capture modes, chosen by measurement

All three verified on macOS 26.5.2 / 25F84, 2026-07-17:

| Mode | Rate | Role | Evidence |
|---|---|---|---|
| `-f exec` (unfiltered) | **~192 lines/s** | binary set + **PATH probing** | 767 lines/4s |
| `-f network` | moderate | endpoints, sockets, **DNS** | 12,714 lines; captured `connect → private/var/run/mDNSResponder` and `socket` rows for a `curl` |
| `-f filesys` (**name-filtered** — see §4.0 for the set) | **~8,200 lines/s** | the path touches | 24,507 lines/3s |
| ~~`-f filesys` unfiltered~~ | **~63,200 lines/s** | **REJECTED** | 252,895 lines / **60MB per 4s** ⇒ ~**5.1GB** and ~57M lines per 900s turn, of which **0.15%** was the target tree |

**PATH probing is real surface and nobody predicted it.** A-exec captures one `execve` **per PATH
candidate**: `/Volumes/…/.venv/bin/git`, `/Volumes/<workspace>/rust/cargo/bin/git`,
`/opt/homebrew/bin/git`, … A profile must account for the probe of every PATH entry, not just the
binary that wins.

### 4.0 Phase ordering — the filesys filter is NOT circular (sol P1-3)

**r2 finding, accepted.** v2 filtered `-f filesys` by "A-exec's binary set" — but that set is an
*output* of the exec capture, so the filter depended on information from the turn it was filtering.
sol is right; the fix is explicit phase ordering (sol's own remedy, which does **not** widen the
R2-only stimulus — it repeats the same brief):

1. **Discovery turns (exec + network, unfiltered):** run the R2 brief `auto` N≥2 times capturing only
   `-f exec` (192 lines/s — cheap) and `-f network`. Accumulate the **binary-name set** ∪ the seat
   process names (`kimi`, `python3`, `git`, `sh`, …).
2. **Filesys turns (name-filtered to that union):** re-run the *same* R2 brief with `-f filesys`
   filtered to the discovered set + `kimi`.
3. **Closure gate:** a **final exec capture** during the filesys turns must surface **no binary name
   absent from step 1's set**. A new name ⇒ the filter was incomplete ⇒ **fail closed, widen, re-run**.
   This is what makes "one turn" honest: it is really *discover-then-measure*, and the gate proves the
   measurement turn introduced nothing the discovery turns missed.

Cost update: A is **not** one turn. It is ~2 discovery + ~2 filesys ≈ **4 turns (~1h)** (corrects the
v2 cost line and §9).

### 4.1 Attribution is an open problem — stated, not waved at

**`fs_usage` has NO ancestry semantics.** Its man page: *"The sampled data can be limited to a list of
process IDs or commands. When a command name is given, all processes with that name will be sampled."*
Its columns carry `PROCESS NAME` (as `name.pid`) but **no PPID**. So there is no descendant selector.

This is not theoretical: **the 2026-07-17 test trace captured a parallel session's work** — `codex`
(3,952 rows), `python3.12` probing `/Volumes/<workspace>/repos/ARB/…`, `grok`, `redis-server`. A
name-filter on `git` catches **every `git` on the host**, not kimi's.

Mitigation, all three REQUIRED (r2 sol P1-4 / grok F5: a recorded risk with no gate is not a
mitigation — the handoff's own principle is *refuse rather than degrade*):
1. **Quiesce the host** for the trace window — no parallel bridge dispatches, no other sessions.
   Verifiable: `ps -axo pid,ppid,comm` at window open must show no bridge/codex/grok/pi processes.
2. **Measure the contamination:** sample `ps -axo pid,ppid,comm` throughout, reconstruct the pid tree,
   and report the count of `fs_usage` rows NOT attributable to kimi's tree as a first-class number.
3. **FAIL-CLOSED contamination gate (new in v3):** if unattributed rows exceed **CONTAM_MAX** (a
   pinned threshold, default **0** under a quiesced host), **the trace is REJECTED and A produces no
   surface** — it does not emit a contaminated-but-labelled table. Honest acknowledgement (sol P1-4,
   grok F5): `ps` sampling races short-lived processes, so a small nonzero count may be *unavoidable
   attribution lag* rather than real foreign IO — therefore the gate also records, per unattributed
   row, whether its process name is in the discovered set (§4.0). Foreign **names** ⇒ hard reject;
   known names with lost lineage ⇒ recorded as attribution-lag with a bounded count. The threshold and
   this split are themselves reviewed, not author-set.

### 4.2 `fs_usage` drop behaviour is UNDOCUMENTED — a GATED risk, not a naked one

`man fs_usage` contains **no** drop/overflow/lost-event language ⇒ it is **unknown** whether it reports
drops, and absence of a warning is not evidence of none. A dropped event is a silent under-allow.
v3 gates it rather than merely recording it:
- **Volume kept low** by the mode split (§4) — the whole reason `-f filesys` is name-filtered.
- **Cross-instrument detector:** the §2 delta "required by B, not in A ⇒ an instrument is lying" is
  the live drop-detector — a class B proves necessary whose paths never appeared in A is *exactly* a
  dropped-event signature, and it **fails the run** rather than shipping.
- **Bounded-loss probe:** run one filesys capture at a deliberately elevated event rate and diff its
  path-set against the normal-rate capture; a divergence quantifies the drop rate at the margin.
**Still an open risk** — but now one with a failing detector, not a disclaimer.

## 5. Instrument B — class-**necessity** under the oracle (NOT path-minimality)

**r2 correction (agy F3, sol P1-2), accepted.** v2 called this "prove minimality / every allow load-
bearing." That overclaims. Dropping a whole class (say `~/.kimi-code/**`) fails the oracle if **any
one** path in it is required — so B certifies the **class is necessary**, and every A-observed path in
that class then enters `SandboxSpec`, incidental siblings included. **B proves class-necessity under
the oracle; it does NOT prove per-path minimality.** The residual intra-class over-allow is a recorded
bound (§9), not a solved problem. A per-path refinement stage is possible future work, explicitly out
of scope for this probe.

Per-allow drop-one on live turns is unaffordable (N allows × 900s); per-allow on *proxies* is what got
v1 blocked. So B drops **semantic classes**, each against a **real turn**:

| Class | Hypothesis |
|---|---|
| repo / worktree | required |
| `.git` internals | required |
| xcrun / toolchain cache (`DARWIN_USER_TEMP_DIR`) | required — the original scar |
| `~/.kimi-code/**` seat state | required (§3) |
| dyld / `/usr/lib` / `/System` | required |
| PATH-probe directories (§4) | **unknown — the interesting one** |
| network endpoint | required |
| TMPDIR | unknown |

~6–8 classes × ~900s ≈ **1.5–2h**. Affordable, and **sound in a way proxies never were**: the
subject under test is the actual seat doing actual work.

**Each drop must make a NAMED oracle fail (§6), never merely change an exit code.**

## 6. The oracle — semantic, and proof-of-work, never exit codes (r2: grok P0 + sol P1-1)

**The r2 finding, verified.** v2 claimed its oracle was `review_viability.py`'s criterion and that it
"discriminated 5/5 R1 and 3/3 R2." **Both false.** The committed predicate at `review_viability.py:151`
is `stopReason == end_turn AND len(text) > 200` — nothing more; its own comment reads *"Heuristic,
deliberately crude."* Applying the stronger oracle below to the 9 committed rows (`derive_evidence.py
da4c2d2`, `oracle_disagreements`): **one row disagrees** — `R2-shell-requiring#1` is `delivered=True`
with **0 citations and refusal language**, i.e. a **refusal scored as a delivery**. So the honest tally
is **R2 2/2** (1800s rows) + R1 5/5, and `af85422` carries that false green (errata
note not included in this copy).

**Why the crude oracle is not merely weak but wrong for THIS probe.** The matrix already proved kimi
**routes around a denied `Bash` using `Read`** (up to 47 tool calls). So under a sandbox that denies
`git`, kimi can still read `_acp.py`, emit >200 chars with `file:line` citations, reach `end_turn` —
and **never inspect the diff it was asked to review**. Any oracle that does not verify kimi *exercised
the denied tool* will green-light exactly the degraded turn B is trying to detect. Citations alone do
not fix this: kimi cites files it *read*, not the commit it failed to `git show`.

**The turn oracle — `DELIVERED` (v3), a proof-of-work oracle:**

```
DELIVERED := stopReason == end_turn
          AND mutations == 0
          AND len(text) > 200
          AND text contains ≥1 file:line citation
          AND PROOF-OF-GIT: the reply quotes the commit SHA-or-subject under review
                            — a fact obtainable ONLY by a successful git invocation,
                            planted by the brief ("state the SHA and one-line subject
                            of the commit you reviewed"). Absent ⇒ NOT delivered,
                            regardless of how much review prose is present.
```

Proof-of-git is the load-bearing addition: it makes the oracle sensitive to the **silent tool
denial** that citation-counting cannot see. It is checkable mechanically against the A-trace/commit,
not by a `file:line` regex (grok's remedy #1).

**For any shell probe:** `set -o pipefail`, per-stage status, and an expected-output assertion
recorded **from the unsandboxed control**. Never a bare `$?` (executed: `false | head -60` → rc=0).

**Two controls, because green proves nothing without them:**
1. **Adversarial self-test** — every probe runs **UNSANDBOXED and must satisfy the same oracle**. A
   probe that fails both ways measures the probe. *This is the control that catches the ARB-profile
   failure mode: its allow-set cannot exec `/bin/echo` (rc=71) while `(allow default)` passes.*
2. **Positive deny control** — deliberately block a known-required access and require the oracle to
   **go red**. Proves the checker can see a failure at all
   (`[[deny-proofs-need-adversarial-verification]]`, `[[vacuously-green-guard-fail-loud]]`).

## 8. Mechanism traps — paid for, do not re-discover

| Trap | Fact |
|---|---|
| `(trace "…")` | **Silently no-ops on 26.5.2.** Parses, runs, emits nothing. This is *why* A is `fs_usage`. |
| `(subpath "/tmp/…")` | `/tmp` is a symlink; Seatbelt matches **resolved** paths ⇒ denies everything incl. intended allows. Use `/private/tmp`. |
| **`(subpath "/a/b")` is NOT a string prefix** | It matches `/a/b` and its contents — **not** `/a/b-c.txt`. A rule that looks like it denies can silently match nothing. (Cost an hour on 2026-07-17.) |
| **A denied exec looks like a MISSING FILE** | `deny process-exec` surfaces as `zsh: no such file or directory: /opt/homebrew/bin/git` — not a permission error. Reads as a broken PATH, invites the wrong fix. |
| Denied **file** ops DO name the path | `touch: /private/tmp/…/t2.txt: Operation not permitted` (rc=1) — reported by the failing program via errno, not by `sandbox-exec`. |
| Sandbox denials ARE in the unified log | `log show --predicate 'subsystem == "com.apple.sandbox.reporting"'` → `[violation] Sandbox: imagent(434) deny(1) mach-lookup …`. A real attribution channel if one is needed. |
| `fs_usage` | Requires root (passwordless sudo verified available). Read-only. |
| `Popen(user=…)` (ARB's `_os_launcher`) | setuid needs root; our seats run as the operator's own OS user. Not reusable. |
| SIP | Enabled; `kimi` (`~/.kimi-code/bin/kimi`, native arm64 Mach-O) is not SIP-protected. |
